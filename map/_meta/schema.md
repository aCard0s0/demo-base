# Schema — the rules of this map

Two card types, closed. When practice and this file disagree, reconcile the same day.

## Card types

| `type:` | Lives at | Carries |
|---|---|---|
| object | `objects/<cluster>/<slug>.md` | a noun: its shape, why, connections, change impact — from `_templates/object.md` |
| process | `processes/<slug>.md` | a verb: input → movement → output, cited steps — from `_templates/process.md` |

Clusters: `identity`, `todos`, `agents`, `platform`. A fifth needs three cards that fit none of these.

## Frontmatter

| Key | On | Values |
|---|---|---|
| `type` | both | `object` · `process` |
| `cluster` | object | one of the clusters above |
| `universe` | object | `live` · `leftover` · `ghost` |
| `status` | both | `stub` · `verified` · `stale` |
| `verified` | verified cards | ISO date the citations were last checked |
| `at` | verified cards | the commit they were checked against |
| `entity` | object | path of the owning file |
| `consumes` / `produces` | process | relative links to object cards |

## Naming

- Slugs: kebab-case, the noun's code name when it has one (`agent-mcp-server.md`), else the product word.
- Citations: `path:line` from the repo root.
- `objects/_index.md` and `effects/CONTEXT.md` are hand-kept catalogs, one line per entry; `AGENTS.md` and
  `routing.md` are generated by `./dbase map sync` and never hand-edited.
